# Architecture decision records

One file per decision that is hard to reverse, numbered in order, never
edited after acceptance. A superseding decision is a new record that names
the old one. `DESIGN.md` says what the system is; a record says why a choice
was made over its alternatives at the time.

Write one when a change touches a shipped format, the verdict function,
policy, signing, storage, a hook, licensing, or the contribution terms.
Copy `0000-template.md`. Status is `proposed`, `accepted`, `superseded by
NNNN`, or `rejected`.
